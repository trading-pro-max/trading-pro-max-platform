# Codex Sovereign Construction State

Codex Sovereign Construction State is the internal build-control layer for Trading Pro Max. It turns construction requests into governed work with constitution, parliament, jurisdiction, task passport, execution permit, prompt compiler, result tribunal, memory lessons, and Founder Command reporting.

Core law: Codex is a licensed construction worker, not a ruler.

Codex may:
- read scoped code
- draft safe changes
- implement approved low-risk tasks when permitted by external workflow
- update docs, tests, copy, and CSS only inside passport scope
- run validation externally through the approved Codex environment
- return reports, diffs, and commits when an external permit allows

Codex may not:
- bypass Founder approval
- bypass Product Truth, Guardian, Legal, or Security gates
- touch secrets or production credentials
- activate billing, broker/feed, live execution, real money, social publishing, or public launch
- expose Founder Command to normal users
- weaken auth/security without review
- change plan activation, pricing, or claims without Founder approval
- claim global launch readiness

Operating loop:
1. Receive construction event.
2. Classify category and risk.
3. Apply Task Constitution.
4. Send through Task Parliament.
5. Assign Jurisdiction Office scope.
6. Generate Task Passport.
7. Decide Execution Permit.
8. Compile Codex-ready prompt.
9. Hold for manual or external approved runner readiness.
10. Judge result in Result Tribunal.
11. Record Product Memory lesson.
12. Report to Founder Command / Presidency.

Current status:
- Level 3.0 draft-only is allowed.
- Level 3.1 submission readiness is allowed for low-risk docs/tests only.
- Web app execution is not allowed.
- Direct Codex calls from the web app are not allowed.
- External submission remains inactive until a separate approved runner exists.
