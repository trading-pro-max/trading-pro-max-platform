# Al-Kawn Desktop Experience Correction

## Definition

`/desktop/kawn` must feel like entering الكون, not like reading a technical dashboard.

The opening screen is the private living entry for Ahmad's electronic universe. It must answer immediately:

- Where am I? داخل الكون.
- Is it alive? Yes: state, pulse, Wake State, and Daily Work Loop.
- What is true? Product Truth is loaded.
- What can it do? Safe internal execution.
- What does Ahmad control? Real money, external decisions, and legal gates.
- What happens next? One next action selected.

## Above-The-Fold Rule

The first screen has four primary areas only:

- Living Universe Entry.
- One Human Message.
- One Next Action.
- Truth / Money / Privacy Strip.

Boot details, reports, capability matrices, rights, gates, Infinity, Operator, and Local Day One remain available lower on the page as secondary technical panels.

## Runtime Rule

React list keys must be stable and section-scoped. Repeated labels like `Daily Work Loop enhancement` must not be used alone as keys.

## Product Truth Priority

Product Truth remains above visual beauty. The correction does not start Local Day One, public launch, billing, payments, withdrawals, real money, broker execution, legal approval, FINMA approval, public الكون, or public ALKON.

## Review Rule

Local Day One remains ready_not_started. Ahmad reviews `/desktop/kawn` again before any start decision.
