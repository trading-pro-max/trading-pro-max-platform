## Why This Comes After Ontological Law

Al-Kawn Ontological Operating Law defines why every entity exists, which layer owns it, what truth source supports it, what Product Truth impact it has, and what stops or blocks execution.

Al-Kawn Visual Map is the next logical step because the law must be visible to Ahmad inside `/founder/universe`. The map turns the ontological law into a clean founder-facing architecture view.

This is not a generated image. This is not public marketing. This is a private canonical map made with code, cards, hierarchy, status chips, boundary labels, and Product Truth labels.

## Node Semantics

Every visual map node must define:

- node id
- Arabic label
- English technical label
- layer type
- owner
- status
- truth source type
- visibility scope
- execution meaning
- boundary type
- relation to origin

## Status Semantics

Allowed statuses:

- active
- active_with_notes
- protected
- blocked
- future
- future_gated
- private_only
- public_future
- compatibility
- cleanup_candidate
- ahmad_decision_required

Infinity Mode and Operator Mode must appear as blocked/future, never active.

## Truth Source Semantics

Allowed truth sources:

- manual_founder_decision
- product_truth
- kernel_enforced
- report_evidence
- test_evidence
- local_project_state
- simulation_labeled
- future_gate_pending

Real claims require real sources. Simulations must be labeled. Unknown or future claims must remain pending.

## Boundary Semantics

Allowed boundary values:

- private_only
- internal_execution
- legal_stop
- money_stop
- public_block
- future_gate
- truth_guarded
- secret_guarded

Legal and money boundaries stop execution for Ahmad. Product Truth violations are blocked.
