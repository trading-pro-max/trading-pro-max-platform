# Origin-Clean Architecture Law

Status: active_with_notes

Official path:

`C:\Users\ahmad\Desktop\ALKON\Pro Max\Pro Max Trading\pro-max-trading-platform`

Origin-clean means every file, folder, route, API, component, style, test, report, tool, and asset must prove purpose, ownership, visibility, safety, evidence, lifecycle, and next fate.

## Primary Layers

Every file has exactly one primary layer:

1. Private Alkon -0
2. Public Pro Max
3. Invisible Operating Layer
4. Tools / Builder
5. Tests / Evidence
6. Docs / Reports
7. Public Assets

## Route Law

- `/` is Pro Max Center.
- `/trading` is the canonical Pro Max Trading workspace.
- `/en` is compatibility only and must not be the primary workspace identity.
- `/founder/alkon` is the private Alkon -0 command universe.
- `/founder/pocket` is the private Alkon Pocket decision center.
- Public navigation must never link to Founder routes or Founder APIs.

## Boundary Law

Public Pro Max code may show public-safe readiness only. It must not render Alkon, Founder Command, Kernel, Zero Truth, Reality Trial, Wake Report internals, Command Passport internals, or private governance language.

Private Alkon -0 code may read and summarize public readiness, but it must remain Founder-only and never execute shell, Codex, payments, billing, broker/feed, live trading, production launch, or external publishing from the web app.

The Invisible Operating Layer translates private truth into public-safe states.

## Lifecycle Law

Anything without clear ownership becomes one of:

- cleanup_candidate
- move_candidate
- archive_candidate
- protected
- blocked
- needs_ahmad_decision

No uncertain file is deleted without proof.

## Product Truth Law

Live execution, real money, broker/feed, billing, production launch, social publishing, fake metrics, trading signals, profit promises, public number-one claims, and regulated/licensed claims remain blocked unless a future Ahmad-approved command changes the legal and technical truth.
