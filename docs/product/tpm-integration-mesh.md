# TPM Integration Mesh

The TPM Integration Mesh defines how Trading Pro Max keeps product truth, plan access, TPM Assistant behavior, blocked-state explanations, safety review, media readiness, private reporting, Diagnostics, Settings, and visual acceptance aligned.

## Canonical Chain

Product Truth -> Plan Entitlements -> Assistant Context -> Why Blocked / State Explanations -> Guardian + Legal Rules -> Journal / Coach -> Content / Media Readiness -> Founder Command Reporting -> Diagnostics -> Visual Acceptance.

## Product Truth

Product Truth is the source for:

- live execution: blocked
- real-money routing: blocked
- broker/feed: guarded/unconfigured
- billing: inactive
- public launch: inactive
- social publishing: inactive
- Pro and VIP: planned/locked unless entitled
- Institutional: future planned
- Islamic/Sharia status: not certified by default
- performance fees: hidden/internal and inactive
- private command tooling: separate from user plans

## Plan Entitlements

Plan Entitlements define:

- Free active paper-safe capabilities
- Pro planned/entitled capabilities
- VIP planned/entitled capabilities
- Institutional future capabilities
- hidden/internal capabilities that must never appear as user-plan features

Public UI exposes only Free, Pro, VIP, and Institutional.

## TPM Assistant

TPM Assistant reads:

- Product Truth
- Plan Entitlements
- State / Error / Blocked explanations
- Journal/Coach readiness
- Settings and Diagnostics context
- account/session state
- account type and Islamic/Sharia truth

TPM Assistant must not expose private command tooling, internal governance detail, performance-fee research, secrets, trade execution, live activation, real-money routing, broker/feed activation, billing activation, or guaranteed performance language.

## Why Blocked

Why Blocked explains unavailable or protected states with:

- user-facing reason
- internal/future condition if appropriate
- safe next step
- severity
- resolver concept

Coverage includes live disabled, real money blocked, broker unavailable, feed fallback, billing inactive, VIP locked, Institutional future, Islamic review required, private command unavailable, public launch inactive, social publishing inactive, auth required, degraded, not configured, and coming later.

## Guardian + Legal

Guardian + Legal classify:

- risky claims
- unsafe assistant intents
- media content
- plan claims
- Islamic/Sharia wording
- billing/live/launch claims
- copied competitor content
- uncontracted brand/company usage

Blocked items provide a safe alternative, reason, review path, and internal escalation when appropriate.

## Content / Media

Content Factory readiness routes content through:

idea -> draft -> brand_review -> guardian_review -> legal_review -> founder_approval -> scheduled/planned -> blocked/archived.

There is no external publishing, no social tokens, no connected social accounts, and no fake metrics.

## Private Reporting

Founder Command reporting receives internal summaries from Product Truth, Plan Entitlements, Assistant readiness, Journal/Coach, Guardian/Legal, Content Factory, Media/AI Video, Treasury, Community, Visual Acceptance, Final Acceptance, what not to approve, and next safe actions.

It remains private, read-only by default, non-executing, and hidden from public navigation and user plans.

## Diagnostics And Settings

Diagnostics shows public-safe readiness for product truth, plan entitlements, Assistant context, Why Blocked, Journal/Coach, Guardian/Legal, Content Factory, private reporting readiness, Visual Acceptance, and internal engines.

Settings prioritizes account/session, current plan, plan capabilities, Assistant level, Journal/Coach readiness, theme/language, account type, and product truth summary.

Neither surface should feel like raw JSON or expose private data, fake metrics, or internal governance terminology to normal users.

## Public Language Rule

Normal users see:

- Free
- Pro
- VIP
- Institutional
- TPM Assistant
- Trading Workspace
- Journal
- Coach
- Academy
- Community
- Premium Reports
- Plans
- Readiness
- Settings
- Diagnostics

Internal Founder/Planet/governance terminology belongs only in internal docs and private command surfaces.
