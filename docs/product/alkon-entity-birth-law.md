# Alkon Entity Birth Law

Nothing is born randomly. Birth converts Founder ideas, product gaps, visual rejection, validation failures, user confusion, support gaps, security risk, media needs, treasury needs, launch readiness needs, cleanup candidates, Assistant intents, public page requirements, and Alkon subsystem requirements into candidate entities.

Every birth candidate must state what is being born, why it is proposed, who it serves, which world it belongs to, whether it is now/later/future/blocked, and which memory lessons apply.

Dangerous activation, raw secrets, bank/card data, public Alkon exposure, shell execution, social publishing, and image generation without explicit request are blocked before birth can continue.
