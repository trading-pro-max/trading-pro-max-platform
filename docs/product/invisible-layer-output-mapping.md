The invisible operating layer maps internal system truth to public-safe copy.

| Internal system | Public output | Founder/internal output |
| --- | --- | --- |
| Product Truth live block | Live execution is not active. | Product Truth confirms live execution remains blocked. |
| Billing readiness | Billing is not active. | Treasury controls remain readiness-only; billing activation is blocked. |
| VIP entitlement state | VIP is planned. | VIP requires entitlement, billing, legal, and safety gates before activation. |
| Founder Command privacy | Hidden, or Private controls are not part of user plans. | Founder Command is private, owner-only, and not exposed in public navigation. |
| Security sovereignty | Safety readiness is active. | Red, blue, purple, incident, evidence, and hardening readiness are tracked internally. |
| Product memory | Journal notes use safe local/session memory where available. | Safe local reports, acceptance, gaps, validation, and build outcomes are tracked. |
| Construction queue | Hidden. | Draft-only build queue waits for Ahmad approval and separate Codex execution. |
| World Interface | Support channels are planned or readiness-only. | External requests are classified without sending, publishing, tokens, or automation. |
| Media Office | Academy, Community, and updates remain draft/review safe. | Media and AI video workflows require brand, Guardian, Legal, and Founder review. |

Public output never includes raw internal vocabulary, secrets, private data, production readiness claims, fake users, fake revenue, fake metrics, fake partnerships, or fake plan activation.
